# Changelog

All notable changes to the "Tablas" extension are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- A DuckDB SQL result is now a real table: it gets column type badges, profile strips and the per-column filter boxes, like any table. A result is kept as a temporary table (the file is untouched) of at most its first 100,000 rows; when the query returned more, the note says statistics and filters cover those rows.

## [0.1.0] - 2026-11-21

First release.

### Added
- CSV viewer — read-only table view via `tablas.csvViewer`.
- Parquet viewer — read-only table view via `tablas.parquetViewer`.
- SQLite viewer (`.db`/`.sqlite`/`.sqlite3`) via `tablas.sqliteViewer`, with a table/view selector.
- Excel viewer (`.xlsx`) via `tablas.xlsxViewer`, with a sheet selector.
- DuckDB viewer (`.duckdb`/`.ddb`) via `tablas.duckdbViewer`, with a table/view selector.
- `tablas.maxRows` setting to cap rows loaded per file (default 5000).
- Requires VS Code 1.90 or newer (the extension host must run Node 20). Works in untrusted workspaces (Restricted Mode); a workspace cannot set `tablas.maxRows` there.
- Theme-aware, XSS-safe rendering (no `innerHTML` anywhere in the webview).
- The SQL box colours your query like a `.sql` file in the editor: keywords, function calls, strings, numbers, comments, types, `NULL`/`TRUE`/`FALSE`, operators and quoted names, in the colours of your **active colour theme** (it reads the theme's syntax colours and your `editor.tokenColorCustomizations`, and follows a theme change straight away, including when VS Code switches themes with your OS light/dark setting). Without a matching theme rule it uses the Dark+/Light+ palette for the theme's brightness. The box is still a normal text box (selection, undo, IME and screen readers work as before); the colours are drawn from a layer underneath, and the box no longer soft-wraps long lines, it scrolls sideways.
- Select cells, rows and columns by clicking, like in DataGrip. Click a cell; click a row number to select the row, a column name to select the column, or the `#` corner to select everything. Shift+click extends from where you started, Cmd/Ctrl+click adds another range, and dragging sweeps. The arrow keys, Home/End, PageUp/PageDown and Cmd/Ctrl+arrows move the selection (Shift extends it), Cmd/Ctrl+A selects all and Esc clears it. Cmd/Ctrl+C copies the selection as tab-separated text that pastes straight into a spreadsheet (cells with tabs, line breaks or quotes are quoted); Cmd/Ctrl+Shift+C adds the column names. The bar above the table shows how many cells are selected and, when they are all numbers, their sum, average, minimum and maximum. It works on tables and SQL results, on rows that are not on screen (a copy reads the data, not the page), and survives a refresh. Alt+click still filters by a cell's value. Cells no longer start a native text selection, since a click now selects the cell.
- **Tablas: Preview dbt Model** for dbt projects. On a model's `.sql` file (editor title bar, explorer or editor right-click menu, or the command palette in a dbt workspace), it finds the model in `target/manifest.json`, finds the DuckDB file (the one named after the manifest's `database`, else it asks), and opens it on the table that model built, in the right schema and under its alias. If the file is already open its panel switches to that table. It says what to do when there is no `dbt_project.yml`, no manifest yet (`dbt parse`), the file is not a model (macro, test, new model), the model is ephemeral, or its table is not in the file yet (`dbt build`). The extension now also activates in workspaces that contain a `dbt_project.yml` so the command is available.
- Column descriptions from your dbt docs: when a DuckDB file belongs to a dbt project (the project above it, else the workspace's only one) and the manifest describes the table, descriptions show in the header tooltips (columns with one get a small ⓘ) and in the column details card. They refresh with the file after each `dbt build`. A manifest larger than 50 MB is not read. Descriptions only show for the database the model was built in (the manifest's `database` must match the DuckDB file's name), so an unrelated database with a same-named table does not get them.
- A SQL box for DuckDB files. Switch **Table | SQL** in the toolbar, type a query (it starts with `select * from <the table you were viewing> limit 5`, and follows the table you view until you edit it) and press Run or Ctrl/⌘+Enter. The result shows as a table with its row count and run time; an error shows DuckDB's message and keeps your text. Only read statements run (`SELECT`/`WITH`/`FROM`, `SHOW`, `DESCRIBE`, `SUMMARIZE`, `PIVOT`, `EXPLAIN`, and read-style pragmas such as `PRAGMA table_info(t)`); anything else, such as `COPY .. TO`, `INSTALL`, `ATTACH`, `CALL`, an `INSERT`, or `EXPLAIN ANALYZE` (which runs what it explains), is refused before it runs. Results are capped at `tablas.maxRows` rows (the box says when a query returned more) and a query is stopped after 30 s. When the file refreshes after a `dbt build`, the query behind the result on screen runs again, so the result follows the data. Switching back to Table keeps your filters and scroll position, and a refresh while you type keeps your cursor, selection and scroll.
- DuckDB tables and views in every schema now show in the table picker, not just `main`. dbt warehouses keep models in schemas such as `staging` or `main_marts`, which used to be invisible. When a file has more than one schema the picker groups by schema (`main` first) with counts, shows the short table name under each header, and searching also matches the schema. Tables outside `main` are named `schema.table`, so two schemas can each have an `orders` table. Statistics and filters work on them too.
- The table picker shows an approximate row count (`~1.2K`) beside each DuckDB table, taken from DuckDB's own table statistics without scanning the table. Views have none.
- DuckDB files reopen on the table you last looked at (remembered per file in the workspace), instead of always the first table.
- DuckDB files refresh themselves when they change on disk, so the `dbt build` → look at the result loop no longer needs closing and reopening the tab. After the file stops changing (and DuckDB's `.wal` file is gone, i.e. the build finished) the view re-reads it and keeps the selected table, your filters (re-applied to the new data), the focused filter box and the scroll position. The toolbar shows when it was updated and how the row count moved (`rows 1,204 → 1,310 (+106)`), "Build in progress…" while it waits, or why a refresh failed (the old view stays). A `↻` button, the editor-title button and the `Tablas: Refresh` command refresh on demand; the `tablas.autoRefresh` setting turns the automatic part off. Tablas works on a copy of the file, so it never holds a lock that could block `dbt`.
- Column filtering for every supported format. Each column header has a filter box in a second header row. Type text to match (case-insensitive), or `!text` (does not contain), `=text` / `!=text` (exact), `=` / `!=` (empty / not empty), `>`, `>=`, `<`, `<=` (numbers compare as numbers; a `YYYY-MM-DD` date compares by day against date and timestamp cells, so `<=2024-01-01` keeps every time on that day), or `\` to search for an operator literally. Boxes combine with AND. Filters search the **whole table**, not just the rows shown (`tablas.maxRows` only limits how many matches are displayed), and the status bar shows the exact match count. Esc clears a box, the `×` in the row-number gutter clears all, and Alt+click a cell filters its column to that value. CSV, Parquet and Excel filter in the extension host; SQLite and DuckDB filter inside the database. Very large tables skip filtering with a reason instead of freezing the editor (CSV, Parquet and Excel tables above 10 million cells).
- Column statistics for every supported format, computed over the whole table (not just the rows shown; `tablas.maxRows` does not limit them). Every column header shows a profile strip: type badge, null share, and a mini histogram for numeric columns or a distinct-count bar for text. Clicking a header profile opens a detail card with nulls, distinct count, min, max, mean and a full histogram with per-bin tooltips. Statistics are requested after the rows are already on screen, so the table never waits for them; a status note next to the row count shows "Computing…", or why statistics were skipped or unavailable for a very large table.

### Changed
- Large tables scroll smoothly and open fast: a table with more than 500 rows (a SQL result, a filter's matches or a file with a high `tablas.maxRows`) now draws only the rows around the viewport, with the rest standing in as empty height, instead of one DOM row per row. A 200,000-row table keeps about 100 rows in the page. Row numbers, zebra stripes, the sticky header, the scroll bar and Alt+click filtering behave as before, and a refresh puts you back at your scroll position.
- Column type badges in the statistics headers are now small icons (a `#` for integers, `#` with a point for floats, a switch for booleans, a calendar for dates, text lines, crossed arrows for mixed, `{ }` for nested/binary, a crossed circle for no values) tinted with the theme's own symbol colours, instead of three-letter text such as `123`/`Abc`. The shape names the type, so high-contrast themes lose nothing.
- The type badge, the profile button's accessible name and the column details card now also show the source's own type when it has one: DuckDB (`BIGINT`, `DECIMAL(10,2)`, `TIMESTAMP WITH TIME ZONE`, `STRUCT(...)`), SQLite (the declared type, none for an expression column) and Parquet (`INT64`, `STRING`, `TIMESTAMP(MILLIS)`, `DECIMAL(10,2)`, `LIST`). CSV and Excel have none, so they show the inferred kind only.
- Faster refresh of a DuckDB file with a filter set: the filter is asked for before the statistics, so the filtered rows no longer wait behind a whole-table statistics scan, and the unfiltered table is no longer drawn for a moment first (the table body stays empty until the filtered rows arrive, and comes back if the filter cannot run).
- A SQL result that a refresh made old while you were looking at the table is re-run when you open the SQL box again, instead of running behind your back on every refresh.
- Looking up a DuckDB file's dbt project (for column descriptions) is remembered instead of walking the folder tree and re-reading `dbt_project.yml` on every table switch and refresh; an edited `dbt_project.yml` is picked up, and a created or deleted one is noticed by the workspace scan.
- The table/view/sheet selector for SQLite, DuckDB and Excel files is now a searchable picker instead of a plain dropdown. Click it (or press Down) to open a list, type to narrow it with the match highlighted, and use Up/Down/Enter/Esc to choose. Tables and views are grouped with counts when a file has both, and views carry a `view` tag.

### Fixed
- Closing a DuckDB tab while its file was still loading no longer leaves the database open and its temporary copy of the file on disk until VS Code exits.
- **Tablas: Preview dbt Model** no longer reports success when the model's table was found but could not be read, and it now brings a panel that is sitting in the SQL box back to the table even when that table is already the selected one.
- Column statistics shown after an automatic refresh can no longer be the numbers from before it: each statistics request now carries a number that the answer echoes, so a slow scan of the old data that finishes after the table was redrawn is dropped instead of landing on the new view (which then showed old counts, or "Statistics unavailable" if the columns had changed).
- Picking a table while a refresh was swapping in the new copy of the file could show "Could not read" on a healthy table (the read hit the old copy, already closed). The pick now goes again on the new copy. This also affected **Tablas: Preview dbt Model** on an open panel, which now also reports "could not open" instead of success when the model's table cannot be read.
- The statistics type badges keep a tinted background on VS Code versions older than about 1.80.
- A DuckDB table switch can no longer pair the table list of the old database with rows of the new one when a refresh lands in between; a SQL query that finishes after its tab closed no longer raises an unhandled error; the dbt project scan ignores a slower, older scan finishing last.
- DuckDB views that refer to their own database by name (`FROM warehouse.main.stg_orders` inside `warehouse.duckdb`, which is what dbt-duckdb stores) now open. They failed with `Table with name "warehouse.main.…" does not exist because schema "warehouse.main" does not exist`, because the viewer read a temporary copy under a different name and DuckDB takes a database's catalog name from its file name. The copy now keeps the file's name (in a private temporary folder).
- The table selector no longer shows as a white box on dark themes. It now uses the active VS Code theme's colours, and native scrollbars follow the dark or light scheme.
- DuckDB files written by DuckDB 2.x (storage version 999, e.g. from the Python `duckdb` 2.0 package) now open. The bundled engine moved from DuckDB 1.5 to 2.0, which still reads older files. A file newer than the bundled engine now fails with a message that says so and suggests updating Tablas, instead of DuckDB's raw `version number 999` error.
- DuckDB views that read files by a relative path (such as `read_parquet('../data/*.parquet')`) now find them next to the `.duckdb` file for local files, instead of failing with "No files found". If one table or view cannot be read, the table selector stays and the error shows in its place, so you can switch to another table instead of the whole file failing.
- Excel date and time cells now show as ISO text (`2024-01-01`, `2024-01-01 10:30:00`, or `10:30:00` for time-only formats) instead of locale- and timezone-dependent JavaScript date text such as `Mon Jan 01 2024 00:00:00 GMT+0100`. The cell's number format decides whether the date, the time or both show. This applies in the table, the statistics card and filters, so date filters such as `>=2024-01-01` now work on Excel date cells. Elapsed-time formats such as `[h]:mm` show as a time.
- Excel merged cells whose top-left cell is a formula now show the formula result in every cell of the range, not `[object Object]`, and formula error results (`#DIV/0!`) show their error text.
